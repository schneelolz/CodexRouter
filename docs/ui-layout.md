# 管理页面与请求指标

当前源码基线为0.8候选功能，管理API1.8、SQLite schema3。版本标签仍由构建命令显式传入，不依据源码默认标签判断版本。

## 导航和布局

- 请求管理：请求明细、历史管理。
- 会话管理：待登记会话、已绑定会话。
- 桌面父菜单用于展开／收起，当前子页自动展开并高亮；手机一级入口配合单行二级导航。
- 请求表拆为供应商、会话ID、模型、请求、Token、延迟、结果、时间八列，普通行高64px。错误码和阶段保留在精确明细中。
- 请求、会话与近期诊断只滚动数据区，表头、标题和分页固定；设置及说明页只滚动内容区域。横向滚动限定于表格。
- 会话子页保留独立分页和未保存的供应商选择，长ID可完整查看和复制；登记不自动重放请求。

61条合成数据下，请求表在1440×900、2552×1274、390×844分别完整显示9、14、4行。具体布局会随字体、浏览器缩放和可用高度变化；浏览器回归覆盖这三个视口及长字段、空状态、实际滚动、复制和键盘操作。

## 延迟和统计

首字与总耗时独立分档，色柱与对应数字同步；缺失段为灰色。阈值参考[sub2api固定版本](https://github.com/Wei-Shaw/sub2api/blob/25608d216bb7be04e4a646830cb065cd09b7d7e9/frontend/src/utils/latencyHealth.ts)。

| 颜色 | 首字 | 总耗时 |
|---|---|---|
| 绿 | 小于10秒 | 小于1分钟 |
| 黄 | 10～不足30秒 | 1～不足3分钟 |
| 橙 | 30～不足60秒 | 3～不足5分钟 |
| 红 | 60秒及以上 | 5分钟及以上 |

非缓存输入仅在输入总量、缓存读取和缓存写入均明确时相减；缺项不当作0。数字以`metrics.known_fields`逐项确认。辅助请求显示“不适用”，旧记录、上游未返回、解析未完成分别解释；已取得的失败用量保留。详情保留输入总量、缓存、输出、推理、精确时间和连接收尾。

`protocol_completed_ms`用于区分协议终止和连接收尾；列表总耗时和TPS在有明确协议终止时排除其后的EOF等待。TPS仍为输出量除以完整生成时长，不扣除首字等待。

## 认证与结果

有效管理页面可见时每5分钟检查续期，剩余不足1小时续至8小时；隐藏不续，已过期凭据不能自行恢复。Cookie、CSRF和同源检查保留。认证失效与网络断开分别提示。

成功终止已可靠解析、字节写入并刷新成功且没有写入失败时，随后客户端关闭连接不再覆盖生成成功。`observation`独立保存协议结果、传输收尾和指标状态。中途取消、实际写入失败和不可靠解析不能升级为成功。旧记录不批量改判、不补造用量。

schema3相对schema2只增加观察元数据列；旧二进制不能直接打开升级后的库，回退需恢复完整升级前数据副本。新界面与真实Go API的合成联调不代表真实账号、完整Codex桌面或子代理兼容性已完成验收。
