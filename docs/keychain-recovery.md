# Keychain 更新与恢复

macOS 使用默认用户钥匙串保存应用凭据。账户登录密码与钥匙串密码通常同步，但账户恢复或迁移后可能不同；授权失败也可能来自应用签名或条目访问规则，不能仅据弹窗判断密码错误。

## 应用更新

本地 ad-hoc 签名随构建变化，旧条目可能拒绝新程序访问。完整 `.app` 签名检查与条目授权是两项不同验证。普通启动禁止交互；`keychain-check` 返回固定状态，`keychain-authorize` 仅在显式本地调用时请求系统授权，由用户决定，不修改全局 ACL 或导出密钥。

若选择新的应用凭据空间，使用 [macOS 说明](macos.md) 中的显式迁移流程：保留原条目，生成新管理凭据，供应商密钥由用户重新录入。迁移不改变默认供应商或会话绑定，不自动重放请求。此机制不找回、解密或重设系统钥匙串密码。

## 系统钥匙串

系统密码恢复与应用升级分别处理。参阅 Apple 官方的 [钥匙串密码说明](https://support.apple.com/guide/keychain-access/if-you-forget-your-keychain-password-kyca2429/mac)，不要反复尝试密码、删除钥匙串文件、清空其他应用条目或向任意程序开放访问。

需要注销或系统恢复时，由用户安排保存工作和恢复凭据的窗口。源码同步与自动化测试不执行这些操作；不要向开发代理发送密码、认证文件或显示密钥的截图。系统恢复后的条目访问和重启解锁需单独验收。
